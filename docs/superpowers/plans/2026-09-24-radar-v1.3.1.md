# Radar V1.3.1 — Deep Ranking Stabilization

## Problem

V1.3 deep stage has two comparability bugs:

- **A — profile-selection bias**: deep shortlist = best_ev Top-30 only, but
  `low_competition`, `authz_api`, `fresh_programs` also weight deep signals.
  Their top rows show `—` for Dup/Opportunity.
- **B — mixed evidence levels**: metadata-only scores (coverage ~63–93%) and
  deep-analyzed scores (~100%) share one ordinal rank; coverage only breaks
  score ties.

## Target architecture

```
279 programs → metadata enrich → metadata scores (stage="metadata")
  → profile-aware candidate union (Top-20 × 4 deep profiles, deduped)
  → deep enrich round → deep scores (stage="deep")
  → frontier check: every deep profile's metadata Top-(K+buffer) deep-analyzed?
    → no: next batch (≤10, budget ≤60) → loop
    → yes: stable | budget exhausted: budget_limited
  → done
```

Two result surfaces: metadata ranking (all rows, evidence badges) and deep
ranking (deep-analyzed rows only, deep ordinal rank). Metadata scores are
never overwritten — deep scores write under the new joined source_hash.

## Constants (types.ts)

`DEEP_PROFILE_IDS` = [best_ev, fresh_programs, low_competition, authz_api]
(priority order, documented). `PROFILE_CANDIDATE_DEPTH=20`,
`STABLE_TOP_K=20`, `STABILITY_BUFFER=10`, `MAX_DEEP_PROGRAMS=60`,
`DEEP_BATCH_SIZE=10`.
