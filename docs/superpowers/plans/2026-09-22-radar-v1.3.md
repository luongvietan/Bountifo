## Architecture decision (coordinator ruling)

Two-stage inside the EXISTING run — no separate job model:

  catalog → enriching → scoring → deep_enriching → deep_scoring → done

- Metadata stage unchanged (4 req/program × ~279 ≈ 1116 req ≈ 19min @60/min).
- Deep stage: Top-N (default 30, `DEEP_ANALYSIS_LIMIT`) eligible best_ev rows.
  Per program: GET_CHANGELOGS (re-fetch — list not persisted) + GET_BRIEF_DOC
  of the previous version + GET_ENGAGEMENT_KNOWN_ISSUES = 3 req → 90 req for
  N=30 (~1.5min). Resumable via `deep_pending_uuids`/`deep_completed_uuids`
  on the persisted run record.
- Deep results land on `snapshot.deep` → included in `source_hash` →
  re-score writes new score rows under the same profile+version; latest-row
  selection surfaces deep-refined scores in existing queries.
- Signals stay null for non-deep-analyzed programs ("not_deep_analyzed") —
  never fabricated.
