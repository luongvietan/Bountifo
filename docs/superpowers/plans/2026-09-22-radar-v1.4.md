# Radar V1.4 — Sourced Access/AuthZ Signals + URL-Shape Surface Classification

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development + dispatching-parallel-agents. Contract commit lands on `main` first; agents run in parallel worktrees with disjoint file ownership; coordinator merges and integrates.

**Goal:** Give the two always-null V1 signals real deterministic sources (`accessibility`, `authz_opportunity`) and close the documented API/web classifier under-detection — all metadata-stage, zero new requests.

**Architecture:** Extend `ApiEngagementData` with three fields already present in the fetched brief doc (`participation`, `credentialsProvided`, `briefText`), extract the duplicated surface classifier into a shared `lib/radar/surface.ts`, then implement two new pure signal modules and a URL-shape classifier extension behind pinned semantics. Profile versions bump only where semantics change (`easy_entry`, `authz_api` → `1.4.0`).

**Spec:** `docs/RADAR.md` (authoritative semantics doc — the Limitations section names exactly the gaps this plan closes). Feature-extraction, scoring, and hashing invariants in `lib/radar/features.ts`, `lib/radar/scoring.ts`, `lib/radar/hash.ts` are binding.

## Global Constraints

- Every signal value is `round4`, `0..1` or `null` (unknown — never coerced, never fabricated).
- `extractProgramFeatures` stays pure: no clock, network, storage, or randomness; `now` is a parameter.
- `detail === null` → every detail-derived signal `null` (`detail_unavailable`); nothing is inferred from the catalog row. V1.4 keeps this — `accessibility`/`authz_opportunity` stay null on the null-detail path even though `catalog.lifecycle_status` exists.
- New `detail` fields are scoring inputs → they join `radarSourceHash`'s `detailProjection`. Golden digests in tests must be recomputed, never hardcoded back to the old preimage.
- Exact-token membership only — never substring matching ("capitol" ⊅ "api").
- No new network requests: V1.4 is metadata-stage only. `siteRequest` allowlist unchanged.
- Feature vector stays exactly 17 signals; `programFeatureVectorSchema` unchanged.
- Profiles touched by newly-sourced signals bump `version` → `"1.4.0"`; untouched profiles keep their versions.
- Reason codes are stable template strings rendered verbatim by the UI; every emittable code must exist in `REASON_TEXT`.

## Signal semantics (pinned — implement verbatim)

### `accessibility` — `lib/radar/accessibility.ts`

```ts
export function accessibilitySignal(
  detail: ApiEngagementData,
  catalog: RadarCatalogItem,
): RadarSignal
```

Sources: `detail.participation` (brief doc), fallback `catalog.lifecycle_status`
(the catalog `accessStatus`), `detail.credentialsProvided`, markers in
`detail.briefText`.

```ts
const SIGNUP_RE =
  /@bugcrowdninja|\bsign[\s-]?up\b|\bself[\s-]?serve\b|\bcreate(?:d|s)?\s+(?:an?\s+|your\s+own\s+)accounts?\b|\bregister(?:ed|ing)?\s+(?:an?\s+|your\s+own\s+)accounts?\b/i;
const FRICTION_RE =
  /\bvpn\b|ip[\s-]?whitelist|whitelist(?:ed|ing)?\s+ip|\bnda\b|non[\s-]?disclosure|identity\s+verification|background\s+check|citizenship\s+requirement/i;
const GATED_RE = /invite|application|approval|waitlist|private|managed|closed/i;

// part = (detail.participation ?? catalog.lifecycle_status ?? "").toLowerCase()
// base: part contains "open" → 0.8
//       part matches GATED_RE → 0.2
//       part non-empty otherwise → 0.5
//       part empty → null
// base null → sig(null, "engagement_detail", "no_access_evidence")
// else v = clamp01(round4(base
//         + (SIGNUP_RE.test(briefText) ? 0.10 : 0)
//         + (detail.credentialsProvided === true ? 0.10 : 0)
//         - (FRICTION_RE.test(briefText) ? 0.20 : 0)))
//     → sig(v, "engagement_detail", "participation_access_rubric")
```

### `authz_opportunity` — `lib/radar/authz.ts`

```ts
export function authzOpportunitySignal(detail: ApiEngagementData): RadarSignal
```

Reuses `lib/model/policyText.ts` exports only (`sentencesOf`,
`techniqueMatches`, `statusOfSentence` — no edits to that file):

```ts
const AUTHZ_SLUGS = new Set([
  "multi-account",
  "cross-account-testing",
  "other-customer-data",
  "cross-tenant",
]);
// accountSurface = 1 iff credentialsProvided === true OR SIGNUP_RE
//   (same regex as accessibility.ts — define it in authz.ts too, do NOT
//   share a module) matches detail.briefText; else 0.
// statuses = sentencesOf(detail.briefText ?? "")
//   .filter(s => techniqueMatches(s).some(t => AUTHZ_SLUGS.has(t.slug)))
//   .map(statusOfSentence).filter(s => s !== null)
// permScore = statuses includes "prohibited" → 0
//             includes "conditional" → 0.5
//             includes "allowed" → 1
//             otherwise → null
// accountSurface === 0 && permScore === null
//   → sig(null, "engagement_detail", "no_authz_evidence")
// permScore === 0 → sig(0.1, "engagement_detail", "authz_surface_rubric")
// else v = round4(clamp01(0.5 * accountSurface + 0.5 * (permScore ?? 0.35)))
//   → sig(v, "engagement_detail", "authz_surface_rubric")
```

Honesty: prohibition is a *low* reading (0.1), not "no opportunity"; a program
with no account surface and no authz-relevant policy sentence reads `null`.

### Surface classifier URL shapes — `lib/radar/surface.ts` (Agent C adds)

```ts
const API_HOST_TOKENS = new Set([
  "api", "apis", "graphql", "grpc", "gateway", "rest", "rpc", "ws",
  "webservice", "service",
]);
const API_PATH_TOKENS = new Set([
  "api", "graphql", "graphiql", "rest", "rpc", "webservice", "service",
  "services",
]);

export function locationLooksApi(location: string | null): boolean
// new URL(location.trim()); non-http(s) or unparseable → false.
// hostname split on /[^a-z0-9]+/ (lowercased) ∩ API_HOST_TOKENS → true.
// FIRST pathname segment ∈ API_PATH_TOKENS → true. Bare /v\d+/ does NOT
// count; "api" deeper than segment 1 does NOT count (pinned conservatism).
```

`classifyTarget` becomes: `api = tokenSet∩API_TOKENS || locationLooksApi(location)`;
`web = tokenSet∩WEB_TOKENS || (!api && isHttpUrl(location))` —
equivalent to today's `isWeb || (!isApi && !isWeb && isHttpUrl)`; the http
fallback still fires only when neither class matched. Used verbatim by both
`features.ts` (`classifySurfaces`) and `diff.ts` (`added_api_targets`) —
one classifier, no drift.

## New `ApiEngagementData` fields (contract)

```ts
participation: string | null;        // engagementConfiguration.participation ?? root.participation
credentialsProvided: boolean | null; // credentialsUrl non-empty string → true; absent → null
briefText: string | null;            // normalized plaintext of data.brief.description + "\n" + data.brief.targetsOverview
```

`briefText` extraction is pure string work (no DOMParser): strip `<[^>]*>` →
single space, decode `&amp; &lt; &gt; &quot; &#39; &nbsp;` + `&#\d+;`,
collapse whitespace. Lives in new `lib/radar/briefText.ts`
(`export function briefTextFromDoc(doc: unknown): string | null`) — returns
null when both sources are absent/empty. `parseEngagement`
(`lib/api/engagements.ts`) sets all three fields `null` — the org-API path
has no source for them. All three join `detailProjection` in `lib/radar/hash.ts`.

## Review Focus

- Brief docs whose `data.brief` lacks `description`/`targetsOverview` →
  `briefText` null → both new signals degrade to their `no_*_evidence` nulls.
- `participation` values outside the pinned bands ("open", gated family,
  other non-empty) — unknown strings read base 0.5, never null-by-accident.
- Targets whose `location` is a bare hostname without scheme
  (`api.example.com` with no `https://`) — `new URL` throws → not API.
  Pinned: only parseable http(s) URLs classify by shape.
- `added_api_targets` in semantic diffs must move identically to
  `api_surface` — same `classifyTarget`, proven by a diff fixture that adds
  an `api.`-host target.
- A brief that *prohibits* cross-account testing must read low (0.1), and a
  brief that merely *mentions* accounts without a normative predicate must
  not fabricate permission (`statusOfSentence` returns null → not counted).
