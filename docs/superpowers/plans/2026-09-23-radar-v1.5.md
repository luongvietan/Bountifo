# Radar V1.5 — Complete the Evidence Plane

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development + dispatching-parallel-agents. Contract commit lands on `main` first; agents run in parallel worktrees with disjoint file ownership; coordinator merges and integrates.

**Goal:** Close every named data gap in `docs/RADAR.md` → Limitations that is closable deterministically: `average_payout` unscored, single-publish diff blindness, unconsumed per-group Known Issues stats, and no relative rank context — plus the documented surface-classifier case bug.

**Architecture:** Three new signals take the feature vector 17 → 20 (`payout_realized` metadata-stage; `scope_momentum` + `ki_concentration` deep-stage via two new deep sub-sources). Result rows gain `percentile` over the eligible cohort. All changes are additive — no existing signal semantics move; only the surface classifier's pathname handling is hardened (lowercase + one percent-decode).

**Spec:** `docs/RADAR.md` (authoritative semantics — this plan edits its Limitations section via Agent E). Verified endpoint evidence in `docs/superpowers/plans/2026-09-22-radar-v1.3.md` §Verified evidence. Feature-extraction, scoring, and hashing invariants in `lib/radar/features.ts`, `lib/radar/scoring.ts`, `lib/radar/hash.ts` are binding.

## Global Constraints

- Every signal value is `round4`, `0..1` or `null` (unknown — never coerced, never fabricated).
- `extractProgramFeatures` stays pure: no clock, network, storage, or randomness; `now` is a parameter.
- `detail === null` → every detail-derived signal `null` (`detail_unavailable`); the three new signals follow the same rule — `payout_realized` included even though it reads `statistics` (the detail-null path means the whole hydration failed).
- New deep sub-objects (`scope_arc`, `known_issues.group_stats`, `known_issues.categories`) are scoring inputs → they join `source_hash` automatically via the existing `deep` projection in `lib/radar/hash.ts` — no hash.ts edit needed, verify with a hash test.
- Exact-token membership only — never substring matching.
- Deep-stage requests stay bounded and are documented: ≤ 1 (KI aggregate) + 1 (changelog list) + 1 (step baseline doc) + ≤ 1 (arc baseline doc) + ≤ 6 (group stats, gated) = **≤ 10 requests per deep candidate**, ≤ 600 per run at `MAX_DEEP_PROGRAMS=60`.
- Reason codes are stable template strings rendered verbatim by the UI; every emittable code must exist in `REASON_TEXT`.
- Feature vector: 20 signals, `programFeatureVectorSchema` strict — the three new keys are REQUIRED in the schema (extractor always emits them; stubs emit honest nulls until agents land).
- Frozen: Exporter V1, Scope Guard V1, Execution Guard V1 — no semantic changes.

export function payoutRealizedSignal(detail: ApiEngagementData): RadarSignal

### `scope_momentum` — `lib/radar/arc.ts` (Agent B)

New deep sub-source: a semantic diff between the current detail and the brief doc `SCOPE_ARC_DEPTH` versions back — catches gradual creep that single-step diffs miss.

```ts
// deepTypes.ts — contract adds:
export const radarScopeArcSchema = z.object({
  status: z.enum(["complete", "unavailable", "no_baseline"]),
  /** Changelog steps spanned (Latest → arc baseline distance). ≥1 when complete. */
  window_versions: z.number().int().min(1).nullable(),
  diff: radarSemanticDiffSchema.nullable(),
}).strict().superRefine((a, ctx) => {
  const ok = a.status === "complete"
    ? a.diff !== null && a.diff.status === "complete" && a.window_versions !== null
    : a.diff === null;
  if (!ok) ctx.addIssue({ code: "custom", message: "arc status/diff mismatch" });
});
// radarDeepEnrichmentSchema += scope_arc: radarScopeArcSchema.nullable()
```

```ts
// arc.ts exports:
export function selectArcBaseline(
  entries: RadarChangelogEntry[],
  latestId: string | null,
  depth: number = SCOPE_ARC_DEPTH,
): { id: string; window: number } | null
// - latestId found at index i → j = min(i + depth, entries.length - 1);
//   j === i (Latest is oldest, or single entry) → null; else {id: entries[j].id, window: j - i}
// - latestId null/empty → head is current: j = min(depth, len - 1); j === 0 → null
// - latestId set but absent → null (never pair with an arbitrary entry — same doctrine
//   as selectDiffBaseline)
// - entries.length < 2 → null

export async function fetchScopeArc(
  slug: string,
  entries: RadarChangelogEntry[],
  latestId: string | null,
  currentDetail: ApiEngagementData,
): Promise<RadarScopeArc>
// selectArcBaseline null → {status:"no_baseline", window_versions:null, diff:null}
// fetch GET_BRIEF_DOC(slug, sel.id) → mapBriefDocument(slug, doc, null, null)
//   → diffBriefDocuments(prevDoc, currentDetail, {from_version: sel.id, to_version: latestId})
//   → {status:"complete", window_versions: sel.window, diff}
// fetch/map throw → {status:"unavailable", window_versions: sel.window, diff:null}
// NEVER throws.

export function scopeMomentumScore(diff: RadarSemanticDiff): number | null
// status !== "complete" → null; only_administrative_changes === true → 0
// s = min(1, 0.35·ai/(ai+8) + 0.25·api/(api+4) + 0.10·ag/(ag+2)
//          + 0.15·[reward_increase] + 0.15·mi/(mi+4))
// ai=added_in_scope_targets, api=added_api_targets, ag=added_groups,
// mi=moved_in_scope — same fact names as opportunityChangeScore, larger
// half-saturations (a 5-publish window accumulates more). Weights sum 1.00,
// every term monotone nondecreasing; reductions contribute nothing.
// Worked: ai=10 net adds → 0.35·10/18 ≈ 0.194; +api 2 → +0.083; +rewardUp → +0.15.
```

`features.ts` helper (contract): `snapshot.deep?.scope_arc` absent/null → `sig(null,"deep_enrichment","not_deep_analyzed")`; `status !== "complete"` → `sig(null,"deep_enrichment",\`arc_${status}\`)`; else `sig(scopeMomentumScore(arc.diff), "deep_enrichment", "arc_momentum")` — null-safe when `arc.diff` is null (defensive; schema refine makes it unreachable).

group_stats: z.object({

```ts
// groupStats.ts exports:
export function parseGroupKiStats(
  raw: unknown,
  groupId: string,
): { categories: Map<string, { unique: number; total: number }> } | null
// - raw must be an array; element(s) whose `id` matches groupId are used
//   (a single-element response matches implicitly when id absent/mismatch —
//   no: pin STRICT — element.id must equal groupId; no match → null/failed).
// - each stats[] entry: name non-empty string, uniqueCount + duplicateCount
//   non-negative ints — else null. children[] ignored (sub-breakdowns would
//   double-count). categories[name] = {unique: uniqueCount, total: unique+dup}
// - any structural violation → null (fetch layer maps to "failed")

export async function fetchGroupKiStats(
  slug: string,
  groupIds: readonly string[],
): Promise<{ status: GroupStatsStatus;
             categories: { category: string; unique: number; total: number }[] | null }>
// - Promise.all over groupIds (siteRequest's bucket serializes anyway)
// - EVERY group must parse complete → aggregated categories, else status
//   "failed" + categories null. NEVER a partial sample: concentration over a
//   subset fabricates precision.
// - aggregate categories across groups by name (unique +=, total +=); sort
//   unique DESC then category ASC (enters source_hash — must be canonical).
// - never throws.

export function kiConcentrationScore(
  categories: readonly { category: string; unique: number; total: number }[],
): number | null
// - null on empty; sum = Σ unique; sum === 0 → null (contradiction: aggregate
//   said issues exist — honest null, not 0)
// - value = max(unique)/sum — the TOP category's share of known-issue volume.
//   High = pressure concentrated in one VRT class (the rest of the taxonomy
//   is relatively unmined); low = spread evenly. Benefit direction in
//   profiles — concentrated pressure leaves unmined surface.
```

Gating (deep.ts — coordinator integrates; pinned here): fetch only when `ki.status === "complete"` AND `unique_count >= KI_GROUP_MIN_UNIQUE` AND count of in-scope groups with non-empty `id` is `1..KI_GROUP_MAX_GROUPS`. Otherwise `group_stats.status`: `"skipped_upstream"` (ki not complete — no aggregate to interpret), `"skipped_low_volume"`, `"skipped_group_count"`. Skips are terminal-ok states: deliberate bounds, not failures. `groups_fetched` = requests actually made; `groups_total` = qualifying in-scope group count.

`features.ts` helper (contract): `deep?.known_issues` absent → `not_deep_analyzed`; `group_stats` absent → `sig(null,"deep_enrichment","ki_groups_absent")` (pre-V1.5 deep rows); `status !== "complete"` → `sig(null,"deep_enrichment",\`ki_groups_${status}\`)`; else `sig(kiConcentrationScore(categories ?? []), "deep_enrichment","ki_concentration")`.

### `percentile` — coordinator.ts `getResults` (contract commit, coordinator)

- Cohort = rows that are `eligible` AND pass the `minConfidence` argument — the set the table actually compares. Ineligible rows → `null` → UI renders "—".
- `percentile = round1(100 · (E − pos) / E)` where `E` = cohort size, `pos` = 1-based position among the cohort in rank order. Top of 279 → 99.6; bottom → 0.0; `E=1` → 0.0.
- Computed over the FULL pre-`limit` cohort (percentile must not inflate when `limit` truncates the table).
- New module `lib/radar/percentile.ts`: `export function cohortPercentile(position: number, cohortSize: number): number` — pure; contract writes it + unit tests.

## Review Focus

- Changelog list with < 2 entries → arc `no_baseline`; exactly 2 → arc == step diff (dedupe the fetch — same doc id must not be fetched twice).
- Group stats on a program whose in-scope groups lack `id` → those groups can't be fetched; if ANY qualifying group is unaddressable the whole fetch must skip/fail — never a partial sample.
- `group_stats.status === "complete"` with categories summing to 0 while the aggregate reported uniques → `ki_concentration` null (`sum===0`), envelope still counts the stats fetch as complete.
- `percentile` when `limit` truncates or `minConfidence` filters → cohort is the full filtered eligible set, not the displayed page.
- A brief doc `SCOPE_ARC_DEPTH` back that fails to fetch while the step baseline succeeds → arc `unavailable`, diff still `complete`, envelope `partial`, `deep_enriched` still counts the diff.
- `average_payout` as `"$0"` / `0` → `normReward(0) = 0` — a real 0, not null. Negative/absent → null.
